🏛️ Full-Stack System Architecture

CivicPulse AI is structured into decoupled frontend, backend, AI, and persistence tiers:

[Browser UI: Leaflet GIS + Chart.js + Vanilla JS SPA]
    │ (HTTP JSON & Multipart Form Uploads)
    ▼
[FastAPI Server: REST Routers + CORS + JWT Bearer Auth]
    ├── [AI Classifier Service (Gemini 1.5 Vision / Heuristic Fallback)]
    ├── [Smart Priority Detection Engine (Explainable Hazard Scoring)]
    ├── [Duplicate Detection (Haversine Distance + Token Jaccard)]
    └── [SQLAlchemy ORM + SQLite Persistent Engine (civicpulse.db)]

🎓 College Project Review & Viva Preparation Q&A

Common questions faculty examiners and project evaluators ask during project defense, and how to answer them:

Q1: How does your AI classify images, and what happens if the API key is not present or internet is offline?
Answer: When configured with an API key, CivicPulse AI leverages Google Gemini 1.5 Flash Vision via REST to inspect visual features and suggest categories with confidence percentages. If the key is absent or offline, it activates a transparent explainable heuristic fallback using Pillow image histograms and filename keywords, clearly labeling it as a fallback so citizens always have full transparency and the freedom to correct the category before submission.
Q2: How does the Smart Priority Detection work? Is it a black box ML model?
Answer: No, it is intentionally an explainable, multi-factor rule-based hazard engine. Evaluators appreciate honesty: a transparent formula combining Category Inherent Risk (e.g. road accident vs park bench), Public Safety Trigger Keywords (e.g. "sparking", "burst pipe", "flooding"), Visual Evidence Attached, and Community Upvotes produces a 1–100 score and assigns Low, Medium, High, or Critical priority with an explicit written justification.
Q3: How do you prevent duplicate complaint tickets in the same neighborhood?
Answer: We implement a composite spatial-textual algorithm. Haversine geodesic distance computes exact metric proximity between coordinates. If another complaint is within 300 meters, it combines spatial proximity with tokenized Jaccard text similarity and category matching. If similarity exceeds 35%, a non-destructive warning appears in the UI, prompting the citizen to upvote the existing ticket rather than creating duplicate municipal backlog.
Q4: How is data stored, and what happens when the server restarts?
Answer: Data is persistently stored in SQLite (civicpulse.db) through SQLAlchemy ORM. Foreign key constraints enforce relational integrity between reports and the status timeline (audit trail). Restarting the application preserves all submitted reports, images, and administrator status changes.
Q5: How is municipal administrative security handled?
Answer: Administrative actions (status transitions, resolution proof uploads, deletions) are secured with stateless JWT Bearer tokens. Passwords are encrypted using PBKDF2 HMAC SHA-256 with 100,000 rounds and random salt. Unauthorized users cannot forge status updates.
